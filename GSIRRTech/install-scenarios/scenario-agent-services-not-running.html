Agent services not running on application server

In Windows Services console, the agent service is stopped or fails to start: rr-v8-agent (display name Rapid Reconciler 8 Agent) on a V8 install, rr-valc-agent (Rapid Reconciler 7 Agent) on V7. Common causes: a Windows Update reboot, the LocalSystem account hit a permission issue on the install root or the DB, a corrupted rr-valc-agent.xml config, or the WinSW recovery loop (restart 10s → restart 30s → reboot) ran through its three attempts and gave up. Often resolves with a service restart.

What you’re seeing

  • Services console (services.msc) shows Rapid Reconciler 8 Agent (or Rapid Reconciler 7 Agent) as Stopped or failing to start.
  • VALC’s Support Center counts the customer under Brokers with no heartbeat, and Troubleshooting Step 2 says the broker is not connected to VALC, so it cannot read the log for you.
  • Symptom may surface elsewhere as agent disconnected on the VALC Clients grid, or database Unknown on the Databases tab.
  • Task Manager shows no java.exe processes (since the parent agent supervises every child, stopping the service terminates them all).
Only one service to look for

Older docs referenced a second service called RapidReconciler Services — that no longer exists. The current installer (post-WinSW migration) registers a single agent service: rr-v8-agent for V8, rr-valc-agent for V7. A V7 customer testing V8 has both, and each one is separate. What older docs called "RapidReconciler Services" is actually the agent’s spawned child java.exe processes (one per RR database), which appear in Task Manager but not in services.msc. See the RR Agent Reference for the parent/child process model.

Walk these checks

Check 1
Restart the service — then give it several minutes
  1. On the application server, open Services console (services.msc).
  2. Find Rapid Reconciler 8 Agent (service name rr-v8-agent), or Rapid Reconciler 7 Agent (rr-valc-agent) for a V7 install.
  3. Right-click → Start (or Restart if it’s in a stuck state).
  4. Confirm the status reaches Running.
  5. Now wait. The agent and its data-services children take several minutes to finish coming up, and they appear one at a time. Count them in Task Manager rather than judging the restart on the first look.
How many processes to expect

One for the agent itself, plus one for each RR database. A single-database customer settles at two; a four-database customer runs five. A count below the expected total means it is still starting, not that the restart failed — wait and count again before moving to Check 2.

If the count has not reached the expected total after ten minutes, or it reaches it and the service then drops back to Stopped, continue to Check 2 — whatever stopped it will have said so in the log.

Running, with the expected process count? Stop here. Otherwise, continue.
Check 2
Inspect logs and credentials
  • With the service stopped, VALC cannot read the log through the broker, so someone on the application server opens the files. The folder is C:\Program Files\Rapid Reconciler V8\logs\ for V8 and C:\Program Files\Rapid Reconciler\logs\ for V7. Once the service runs again, Troubleshooting Step 2 reads the log for you.
  • Open rr-valc-agent.wrapper.log in that folder — this is WinSW’s own log and captures service start/stop attempts plus the JVM launch arguments. If the wrapper couldn’t launch the JVM (missing JAR, bad path, JRE error), it’s logged here.
  • Then check the output and error logs (rr-valc-agent.out.log and rr-valc-agent.err.log on V8, today’s rr-valc-agent_YYYYMMDD.out.log and .err.log on V7) for the Java-side startup error if WinSW did launch the JVM but the agent died early. .err.log empty = JVM didn’t crash; non-empty almost always tells you what blew up.
  • By default the service runs as LocalSystem (the shipped WinSW config has no <serviceaccount>). If IT changed it post-install to a custom account, verify those credentials are still valid — a recent password rotation can break it.
  • Check Windows Event Viewer → Application log for related errors at the time of failure; WinSW emits Service-Control-Manager events here too.
If the wrapper log or .err.log indicates a config issue, escalate to a senior tech to investigate the agent installation.
