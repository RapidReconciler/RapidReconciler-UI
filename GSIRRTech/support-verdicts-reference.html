Support Verdicts Reference

What each verdict on VALC 2.0’s Support Center and Troubleshooting page means, and what you do about it. The last section covers what the customer sees on the same problems in V8, so you can match their screenshot to your screen.

Where to look, in order

  1. Support Center (VALC home). It counts problems across every customer. A non-zero counter names the screen to open next.
  2. Troubleshooting, with the customer and database picked. Read the bands top to bottom: versions, agent log, SSIS, B to C, roll forward. The magnifier on a customer’s band in Client Management opens it with that customer already picked.
  3. The customer’s own screen. If the customer sent a V8 error or a screenshot of Administrator › Troubleshooting, use section 7 to find the matching VALC band.
  4. The customer scenario pages. When the fix is on the customer’s side, send them the matching page from the Help Desk rather than writing the steps out again.

Customers have no VALC access. Anything that has to happen on their side goes to them by email or phone: “ask the customer to have their DBA start SQL Server Agent”, not “start SQL Server Agent”.

1. Support Center counters

The Troubleshooting card turns red when any red counter is above zero and amber when only amber counters are. “Nothing failing” means all eight checks are clear. It does not read the agent log; see section 8.

2. Step 1: which customer and database

  • The agent chip reads current, update to X, upgrading or cannot upgrade, with the reason beside it, for example “No heartbeat in 5 minutes.”
  • Each database row has DB, Services and SSIS chips. Amber update to X means a newer release is available, which is not a fault on its own.
  • “That customer has no database set up yet, so there is nothing to troubleshoot.” The customer is registered but nothing is installed. Go to the Deployment Center.

3. Step 2: agent log

Picking a database asks the customer’s broker for that database’s recent lines (broker 2.8.0 or later) and analyzes them in the browser. You no longer ask the customer for an out.log first. Load out.log… is the fallback for an older broker, a V7 customer, or a log the customer has already sent.

When the log cannot be read

The band reads “Log not read:” followed by one of these reasons.

Reason on the bandWhat you do
“The customer’s broker is not connected to VALC (last heard from …)”The broker is down or cannot reach GSI. Ask the customer to check the agent service on their application server, then its outbound rules (Firewall & DNS).
“The customer’s broker is version X, and this needs 2.8.0 or later.”Upgrade the broker from Deployment Center › Fleet Upgrades (Broker). A broker older than 2.2.0 needs a new Agent Installer run on the application server instead. Until then, use Load out.log….
“The customer’s broker did not answer within N seconds.”It may still be working. Check the broker’s heartbeat before you try again.
“This database has no uuid yet”The database is not provisioned to a Services instance yet. Finish its Deployment Center steps.
Anything else (“could not run this”, “answered with HTTP N”, “a log answer VALC could not read”)Use Load out.log… and copy the band’s sentence into the engineering ticket.

When the log was read

The verdict is Critical, Review or Looks OK. Each flagged line carries its own “What to do”. The ones you will see most:

LineColourWhat it usually is
Can’t reach VALC at allcritOutbound TLS from the application server is blocked: a firewall, an inspecting proxy or a data-loss tool.
Don’t trust VALC’s security certificatecritUsually right after a certificate renewal. Engineering pushes an updated truststore. See Certificate Management.
Agent cannot reach a monitored databaseflagRight after a reboot it clears on its own within a few minutes. If it stays, SQL Server is down, the login is refused, or the database is offline.
Instance start timeoutflagThat database’s Services instance did not start in time. Restart it from the Databases tab and read the next lines.
Briefly lost contact with VALCflagOnce is a blip. Repeated lines are a real network problem on the path to GSI.

For a line the analyzer does not recognise, paste it into the Log Analyzer, which has the full rule list.

4. Step 3: SSIS and Check SSIS

VerdictColourWhat you do
“An SSIS load is running now.”amberWait. It is working.
“Last SSIS execution succeeded”greenNothing.
“Last SSIS execution failed” (or cancelled)redRead the red What failed banner. Its first error names the connection or the step.
“No SSIS catalog executions yet.”noneThe package has not run on this database. Check the Deployment Center SSIS steps.

Check SSIS tests the catalog itself. Each line that is not ready says what is missing:

  • CLR integration or SSISDB catalog missing: the customer’s DBA does the one-time catalog setup in Installation Prep (Overview, the SSISDB callout).
  • Proxy lines (“SQL Agent proxy RapidReconciler SSIS not found”, “The proxy is disabled”, “not granted the PowerShell subsystem”, “rruser may not use the proxy”): ask the customer to have a sysadmin run install Script 4 with the Windows account they set up for it. Script 4 is also the answer after that account’s password changes.
  • SQL Server Agent not running: ask the customer to start it and set it to Automatic.

Install-time SSIS failures have their own pages: SSIS deploy permission denied and SSIS driver mismatch.

5. Step 4: B to C

The verdict line above the table is the server’s reading of both the B to C log and SQL Server Agent’s job history. The table headline below it counts log errors only. When they disagree, the verdict line wins.

Verdict starts withColourWhat it means and what you do
“The last scheduled B→C FAILED at”redThe SQL Agent job failed. The sentence quotes the job, the step and the SQL error. Use Investigate with AI for a diagnosis, then fix the cause and run it again.
“N current error row(s)”amberA step logged an error and has not run clean since. An error that a later clean run cleared is counted as resolved, not current.
“A scheduled B→C is running now”amberWait.
“Last scheduled B→C succeeded N days ago … SQL Agent job J is disabled”amberThe data is going stale because nothing runs it. Ask the customer to have their DBA enable the job.
“… The job’s schedule (daily at 02:00) is disabled”, or “has no schedule”amberSame cause, one level down: the job is enabled but its schedule is off or missing. Ask the customer to have their DBA enable or add the schedule.
“Last scheduled B→C succeeded 3 days ago (…); expected daily at 02:00.”amberLate: older than twice the schedule’s period. SQL Server Agent was probably stopped or the server was down. Ask the customer to check that SQL Server Agent is running and set to Automatic.
“No SQL Agent refresh job is configured for this database”log’s colourThe refresh job was never provisioned. Deployment Center Step 7.

The customer-side version of a stale B to C is Data looks old and isn’t refreshing.

6. Step 5: roll forward

  • green “Roll forward intact across N rows.” Nothing to do.
  • amber “N GLOK breaks and N VarOK breaks in the roll forward.” This is analyst work, not a fault. The customer’s analyst works it on V8’s Account Roll Forward page. The Excel export lists each finding with its remedy.

7. What the customer sees in V8

An error that ends with “Reference:”

Every V8 page now shows the server’s own refusal sentence, then (HTTP nnn), then Reference: <id> when the data service sent one. The page footer repeats the reference. Ask the customer for the whole sentence and the reference.

  • The reference is the request id. The same id is on that request’s lines in the database’s own service log, services-<port>.log in the agent’s logs folder, and on the Service log sheet of the diagnostics workbook from Administrator › Troubleshooting.
  • A sentence the server wrote, such as “That database is not on your account. (HTTP 403)”, is the answer as written. Check that user’s database rights in VALC.
  • “Sign out and sign in again” (401) is an expired or idle sign-in. V8 signs a user out after 30 minutes without activity.
  • A 404 that says the server’s version is older than the page expects means that database’s Services release is behind. Check its Services chip in Step 1.

8. Readings that mislead

  • “Nothing failing” next to a red agent log. The Support Center does not read Step 2; its card says so. Open Troubleshooting for the customer before you call it clear.
  • V8 shows green while your Step 4 is amber for a disabled schedule. V8’s reconciliation row reads the last run, not the schedule. If the last run finished, the customer sees green until the data is visibly old. Your Step 4 is the earlier warning.
  • The same SSIS state, two colours. A running load is amber in VALC and green in V8. A cancelled one is red in VALC and amber in V8. Read the sentence, not the colour.
  • HTTP 400 “This combination of host and port requires TLS”. The agent is up and serving HTTPS; the caller used http://. Probe the database’s Domain URL over https://.
  • A slow answer is not a firewall. Since Services 8.0.49 a reply that arrives late is amber with the elapsed time. Red with firewall advice means the connection itself failed.
