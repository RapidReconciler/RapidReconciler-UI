Full Perpetual Details

Every row behind the Perpetual figure on Home, for one company at one period end. Use it to see which items, branches, locations and lots make up that number.

Product: RapidReconciler V8 Module: Inventory Press Ctrl+F (or ⌘+F) to search this page

What the page shows

You open this page from Home, through the Full details link on the Perpetual card or the one on the Cardex Variance Framework.

The page shows one company at a time, with balances as of the last day of the period.

The figures are RapidReconciler’s perpetual inventory. It starts at go-live from each item’s on-hand quantity and unit cost, and every receipt, issue, adjustment and transfer updates it as it posts. A row can carry an amount at zero quantity; Zero-Balance Rows explains why that happens and when it matters.

The scope band

The navy-edged band under the page title shows what the figures cover.

  • Database: the RapidReconciler database you’re signed in to.
  • Company: the company on screen. When you have access to more than one, click it to pick another.
  • Period: the period end the balances are stated at. It follows the period you picked on Home, so change it there.
  • Currency: the currency the amounts are in.

The ? at the right end of the band opens this guide.

The three report buttons

The buttons at the top right each produce an Excel workbook for the company on screen. They stay greyed out until the page knows which company that is. The note beside them says what it’s waiting for.

  • UOM Conversions: items with no unit-of-measure conversion for this company, which are the rows showing -9999 in Quantity.
  • Frozen Cost: items whose frozen cost differs from their unit cost. The rows go through the Export Analyzer, and the workbook explains what it found, why, and how to correct it.
  • GL Class: items whose branch and location records carry different GL classes, analyzed the same way.

Asking RapidReconciler AI

The RapidReconciler AI card answers questions about the figures on this page.

  • How is perpetual inventory calculated? explains how the balance is set up at go-live and kept current after that.
  • How are we trending? reads the perpetual balance period by period. For each change, it says whether more or fewer units (volume) or a different unit cost (cost) drove it, and names the item behind it.
  • Have a question? Just ask. Type any question and press Enter. The answer draws on the same figures and the same period history.

Under each answer, What was sent shows exactly what went to the AI, so you can check what the answer was based on.

Residual noise

Residual noise is rounding left in the perpetual: rows with zero quantity that still carry a tiny value. The card on the right sets these rows aside so the grid shows the balances worth reviewing.

  • Residual Optimizer finds the natural break between that rounding and real balances, and hides everything below it. Once it has run, the button reads Re-optimize.
  • The slider fine-tunes how many rows are hidden.
  • Inventory / Filtered switches the grid between the kept inventory and only the rows set aside, so you can check what was hidden.
  • The readout (for example Dust hidden 388 rows · $5.97) shows how many rows are set aside and their total value.
✓
Nothing is deleted

Hiding residual noise only changes what the grid shows. No balance is changed, the Perpetual total doesn’t move, and the Excel export still includes the hidden rows on a separate sheet.

The Details grid

Click Details to open or close the grid. The Perpetual total beside it stays visible either way. That total includes the residual rows.

Controls above the grid

  • Lot detail: when it’s off, the grid shows one row per item, account, branch, UOM and GL class, and an arrow on the left expands an item held in more than one lot or location. Turn it on to give every lot and location its own row.
  • Search rows: finds text anywhere in the visible columns. Start with ^ to match only the beginning of a value, so ^468- finds item 468-100 and skips X-468-100.
  • Excel: downloads what you’re looking at, with your filters, visible columns and column order. The first sheet holds the inventory and the second holds the residual rows. The top of the file names the database, company, period and currency.
  • Columns: shows or hides columns. The pill counts the visible columns out of the total.
  • Row count: for example 16,654 rows of 17,042, the rows left after search, filters and residual hiding, out of the total.

Column headers

  • Click a header to sort by it. Click again to reverse the sort.
  • Click the funnel on a header to filter that column to the values you pick.
  • Drag a header to move the column.

Icons at the start of each row

  • Eye: hover to see the item ledger transactions behind the row’s totals. The popup has its own Excel button.
  • Sliders: opens the item in Cardex Variance, where you adjust its balances.

The page remembers your columns, column order, sort, filters, Lot detail setting and residual setting in this browser, so it opens the way you left it.

Reading the columns

Most of the columns are fields you know from JD Edwards. These are the ones that need a closer read.

ColumnWhat it means
QuantityOn-hand quantity in the item’s primary UOM. A value of -9999 marks an item with no unit-of-measure conversion, so RapidReconciler couldn’t state a quantity. The UOM Conversions button lists these items.
AmountThe extended value of the on-hand quantity, in the band’s currency.
AccountThe inventory account carrying the row’s value: business unit, object and subsidiary.
GL ClassThe item’s GL class code, which routes its value to an account.
Curr CostThe unit cost RapidReconciler matched for the row, read from a cost record.
Calc CostAmount divided by Quantity: the cost the stock on hand is actually carrying. Zero when the quantity rounds to zero. A gap between Curr Cost and Calc Cost is worth a look.
CMThe cost-ledger code of the cost record RapidReconciler matched. It tells you which cost row was used, not the item’s assigned cost method in JD Edwards.
STStocking type from the item branch record (S stock, M manufactured, P purchased). It describes how the item is supplied and doesn’t flag a problem.
Qty Var / Amt VarThe stored cardex variance, in quantity and in money: how far the item ledger moved since its reset baseline, less how far on hand moved over the same span. These are the same figures as the Cardex Variance grid. They only show for rows that carry a reason code, so a zero here doesn’t mean the item has no variance. Check Cardex Variance for that.
Branch CoThe company the row’s branch/plant belongs to, which can differ from Company.
Lot, Lot Status, Lot Exp, Lot BodThe lot or serial number, its status code, and its expiration and best-before dates from the lot master.
Sales Code 01–10, Purch Code 01–10Category codes from the item branch record. They’re codes, never amounts, and what they classify depends on how your JD Edwards is set up.
!

The same item on several rows. If an item’s GL class was changed while it had stock on hand, it can show on more than one row, one for each GL class. The safe way to change a GL class is to adjust the item to zero under the old code, change the code everywhere it’s set (item branch, item location and open orders), then adjust the stock back in under the new code. The GL Class button finds items where the code was changed in one place and not the other.
