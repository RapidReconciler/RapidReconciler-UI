DMAAIs

An audit of your JD Edwards distribution AAI setup. RapidReconciler checks the F4095 rows for setups that are known to cause posting problems, lists what it finds as a worklist, and records how you dealt with each finding.

Product: RapidReconciler V8 Module: Inventory Press Ctrl+F (or ⌘+F) to search this page

What the page shows

You open this page from Home, in the Analyst view. On the Data Health tab, the Model DMAAI Table band has a DMAAIs link, which opens the page on the Model tab for the company you’re working in.

The page reads the DMAAI setup as it is in JD Edwards today. It has no period. Entries that posted earlier may have used a different setup from the one the findings describe.

Access is checked for the database you’re signed in to. Your role needs DMAAI access on that database, and the Administrator module has to be enabled on that database. Without both, the page shows Access denied and tells you to contact your administrator or pick a different database from the user menu.

The Company pill

The Company pill beside the page title narrows the page to one company. Click it and pick a company, or pick All companies to clear it.

  • The list holds only the companies you’re working in on Home. When you’re working in some of your companies and not all, the pill reads All in scope and the list’s first entry is All companies in scope.
  • It narrows the Fix first and Ask the customer lists, the four module tabs, and the tab counts. A finding with no company (an AAI series outside the standard range, for example) stays visible whichever company you pick.
  • It doesn’t narrow Model or Exception GL. Those two tabs show every company you’re working in on Home.
  • The page remembers your pick for each database.

If a link asks for a company outside the companies you’re working in, the pill reads Company followed by the number and not in scope, and the page shows nothing rather than another company’s setup.

The headline and the analyzer caveat

Under the title, the headline says how many configurations were flagged for your review. With it, Last analyzed gives the date of the analysis and Configurations audited gives how many F4095 rows it read.

Click Read the analyzer caveat before acting on findings to open the caveat. It explains that the audit is a starting point and not a complete review, that it reads today’s setup while posted journal entries reflect the setup on their post date, and that DMAAI changes should be tested in a non-production environment before you apply them in JD Edwards.

The tabs

Analysis is the default tab. The number on each tab means something different:

  • Model: how many baseline rows there are for the companies you’re working in.
  • Exception GL: how many item rows carry a GL class missing from the AAI master.
  • Analysis: how many findings are still to deal with, meaning their status is Open, In Progress or Still Flagged.
  • Sales, Inventory, Manufacturing and Purchasing: how many F4095 rows on that tab belong to a finding that’s still to deal with. Rows that no finding matched aren’t counted.

Model

The Model tab holds the grid titled Model · F4095 baseline: the baseline AAI configuration, what the account rules should look like for each company, transaction company, AAI table, order type, document type and GL class. Use it as the reference while you work through the findings.

Next to the title, a badge shows where the baseline’s approval stands: Model approved (with who approved it and when), Model changed since it was last approved, or Model not approved yet. The badge is information only. Nothing on this page approves the model.

Above the grid, Search rows… finds text in any column, Excel downloads the rows you’re looking at, and the count shows the rows left after your search.

Exception GL

The Exception GL tab holds the grid titled Exception GL · items with GL classes not in the AAI master. It lists items whose GL class isn’t in the AAI master. This is an item setup issue, separate from the AAI rule findings on Analysis.

A GL class you’ve listed as a valid exclusion, under document type 98 on DMAAI 4152, is left off this list.

The grid has the same Search rows…, Excel and count controls as Model. The Excel file adds a total row for Quantity and Amount.

Analysis

The Analysis tab is the worklist. It has three parts.

Fix first

Setups that will post wrongly and need correcting. Each finding has an ID starting with F. Two kinds of finding land here:

  • A debit AAI and its credit AAI route to the same account, so postings net to zero. The pairs checked are 4240/4220, 4122/4124, 4126/4128 and 4134/4136.
  • On one of those pairs, document type IT routes the debit and the credit to different accounts, so an inventory transfer doesn’t wash to zero between branches.

The progress bar counts a finding as cleared when its Answer is Fixed or Intended, and reads, for example, 3 / 8 cleared.

Ask the customer

Setups that may be deliberate, so someone who knows the business has to say. Each finding has an ID starting with Q. Three kinds of finding land here:

  • One AAI of a pair is set up for a document type and GL class where its partner isn’t.
  • Most rows for an AAI and GL class use one subsidiary, and a few use a different one.
  • An AAI series sits outside the standard 3000 to 4499 distribution range.

The progress bar counts a finding as answered once it has any Answer, and reads, for example, 2 / 5 answered.

Ignore for now · self-surfacing

The card at the bottom, headed These will surface as JDE posting failures if they ever matter, covers combinations of AAI, GL class and company that aren’t set up at all. The audit doesn’t flag those: if a missing setup ever matters, JD Edwards stops the posting with an error when a transaction reaches it.

Answer, Decision and Status

You respond to each finding in the last three columns. Answer is what you concluded, Decision is a free-text note for why (its placeholder reads Notes · the why), and Status follows from the Answer. You can’t set Status yourself.

AnswerStatus it setsUse it when
(empty)OpenNobody has looked at the finding yet.
IntendedClosed by intentThe setup is deliberate and stays as it is.
Needs reviewIn ProgressSomeone is looking into it.
FixedResolvedThe setup has been corrected in JD Edwards.

A saved response can also come back with the status Still Flagged. The tab counts treat it like Open and In Progress, as work still to do.

Your answers are stored against the analysis they were made on. If the earlier answers can’t be read, a banner says so, and every finding shows as untriaged until you reopen the page. Don’t record new answers until they’re back.

Controls above the grid

  • All rows: click to cycle the row filter through All rows, Hide intended (hides rows whose finding is Closed by intent) and Open only (also hides rows whose finding is Resolved).
  • Search rows…: finds text in the visible columns.
  • Excel: downloads the rows you’re looking at, with your filters and visible columns.
  • Columns: shows or hides columns. Show all turns them all on, and Reset to defaults also restores the column order and clears the sort.
  • The count reads, for example, 120 rows of 412 when filters are hiding rows.

Click a header to sort by it, and again to reverse the sort. The funnel on a header filters that column to the values you tick, with Select all, Select none and Clear filter. Drag a header to move the column. Each tab remembers its own columns, order, sort and filters in this browser.

When you arrive from a finding’s Reference link, a banner above the grid reads Focused on finding with the finding’s ID and how many rows match. Click Clear focus to see the whole tab again.

Rows whose finding is Closed by intent or Resolved are dimmed.

Saving your answers

Changing an Answer or a Decision doesn’t save it. A bar appears at the bottom of the page reading You have N unsaved changes, where N is the number of findings you’ve changed.

  • Save stores your answers. The bar shows Saving… and then Saved., and closes. If the save fails, it says so and keeps your changes on screen.
  • Discard puts every finding back to its last saved answer and decision.
!

Changing an Answer updates the Status, the progress bars, the tab counts and the module grids straight away, before you save. Save before you leave the page, or the change is lost.
