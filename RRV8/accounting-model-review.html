Model DMAAI Review

The model DMAAI table (4152 PI) is what RapidReconciler reads on every import to decide which GL account each inventory transaction posts to. The goal here is to confirm every GL class used in inventory processing maps to the correct account, then sign off on the model.

How this works Confirm the mappings, then sign off

Only your team can approve this — RapidReconciler shows the mapping and does the checking, but the accounts belong to your JD Edwards setup.

  1. Read the two numbers. GL-class → account mappings are what you’re confirming; GL classes excluded aren’t counted in reconciliation — confirm each exclusion is deliberate.
  2. Review row by row. Each row reads as a sentence. Mark OK if the account is right, or Change and note what it should be.
  3. Send a change request. Download change request (.xlsx) turns your flagged rows into a punch list for whoever maintains your DMAAIs.
  4. Sign off. Tick the box and Approve the model. If any row is flagged, sign-off is held until the fix lands in the next refresh.

A re-review tag means the live account changed since you marked it OK — open the row and confirm it again.
