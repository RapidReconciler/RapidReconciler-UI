Reload GL Data

When the account roll-forward shows a GL break that posting batches won’t clear, this clears RapidReconciler’s copy of the general ledger from the earliest broken period forward. JDE re-pulls it on the next scheduled refresh.

This is an administrator function. Contact your administrator to reload GL data.
Couldn’t reach the data service —
A data refresh is running. Reloading now would collide with the load that’s rebuilding these tables, so it’s paused until the refresh finishes. This re-enables on its own.
Your JDE data is never changed, and this does not pull from JDE now. It clears RapidReconciler’s working copy; the GL comes back on the next scheduled refresh. Refreshes load the JDE system, so they only run on the schedule — that period stays incomplete until then.
