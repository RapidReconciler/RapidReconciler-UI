Server & database For your IT

RapidReconciler says the database is offline

GSI watches each RapidReconciler database from its side. A database reads offline when the RapidReconciler service for it stops answering. The cause can be that service, SQL Server, the database itself, or the server they run on. The checks below go from the most specific to the most disruptive, so the server only gets restarted if nothing smaller fixes it.

What you’re seeing

  • RR support has told you that one of your RapidReconciler databases reads offline.
  • Users may also report that they can’t sign in, or that the pages are empty. Those symptoms have their own runbooks, I can’t log in and User sees no data after login. If RR support has said the database is offline, start here.
  • It affects every user of that database at once.
  • On RapidReconciler V8, Administrator › Troubleshooting has a Server to its database row. Amber means the database answered, but slowly or with every connection busy; run the checks again in a few minutes before you work through the steps below. Red means the server could not reach the database at all; start at Step 1.

Try these steps in order

✉
Hand off to your IT
These checks run on your RapidReconciler application server and your database server. Click to draft an email to your IT with the steps filled in.
Step 1
Is the RapidReconciler agent service running?
When this applies: always. Start here.

The agent is a Windows service on your RapidReconciler application server. It runs the RapidReconciler services for every database on that server, so when it stops, every one of those databases reads offline.

  • On the application server, open services.msc.
  • Find Rapid Reconciler 7 Agent (service name rr-valc-agent) or Rapid Reconciler 8 Agent (service name rr-v8-agent). Which one you have depends on your RapidReconciler version. A server running both versions lists both.
  • If its Status isn’t Running, right-click it and choose Start.
  • Open Properties and check that Startup type is Automatic, so the agent comes back on its own after a server reboot.
  • Give it a few minutes to start the database services, then ask a user to sign in.

There is one Windows service per version. It starts a separate java.exe for each database, and those show in Task Manager but not in services.msc. Start and stop them through the service, so the children shut down cleanly; ending java.exe in Task Manager skips that.

Back online? Stop here and let RR support know. Service already running, or it stops again? Continue to Step 2.
Step 2
Is SQL Server running, and is the database online?

The agent can be running while the database underneath it is unavailable. On the database server:

  • In services.msc, check that SQL Server (MSSQLSERVER) is Running. A named instance shows as SQL Server (instance name).
  • In SQL Server Management Studio, connect to the instance and run:
SELECT name, state_desc
FROM sys.databases
WHERE name LIKE 'RapidReconciler%';
  • Every RapidReconciler database, for example RapidReconciler_Prod, should read ONLINE.
  • Any other state, such as OFFLINE, RECOVERY_PENDING or SUSPECT, is one for your DBA. Send them the database name and the state.
SQL Server running and every database ONLINE? Continue to Step 3. Your DBA fixed a database state? Restart the agent service from Step 1 and ask a user to sign in.
Step 3
Is the database server’s disk full?

When the drive holding a database’s data or log file fills up, SQL Server can’t write to it, and RapidReconciler stops with it.

  • To see which drives hold the RapidReconciler files, run:
SELECT DB_NAME(database_id) AS database_name, type_desc, physical_name
FROM sys.master_files
WHERE DB_NAME(database_id) LIKE 'RapidReconciler%';
  • In File Explorer on the database server, check the free space on each of those drives, and on the drive that holds TempDB.
  • If a drive is full, have your DBA free space on it before you restart anything. A server restarted with a full disk comes back with the same full disk.
Space freed? Restart the agent service from Step 1 and ask a user to sign in. Plenty of free space? Continue to Step 4.
Step 4
Restart, then tell RR support
When this applies: Steps 1 to 3 found nothing, or fixing what they found didn’t bring the database back.
  • Restart the agent service first. In services.msc, right-click the agent from Step 1 and choose Restart. This restarts the RapidReconciler services for every database on the server, and it’s quicker than a reboot.
  • If the database still reads offline a few minutes later, restart the RapidReconciler application server.
  • When the server is back up, check that the agent service is Running (Step 1).
  • Email RR support to say you’ve restarted. GSI checks from its side that the database reads online and replies to confirm.
✉
Tell RR support you’ve restarted
Draft an email asking RR support to confirm the database reads online from GSI’s side.
RR support confirms the database is online? You’re done.

Still not resolved?

Escalate to RR support

If the database still reads offline after a restart, or Step 2 turned up a state your DBA can’t clear, email RR support. Say what each step found: the agent’s status, the database state, and the free disk space.
